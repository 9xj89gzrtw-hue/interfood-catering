## KPI ДИЗАЙНА — КРИТИЧЕСКИ ВАЖНО

Сайт должен соответствовать **всем** критериям премиум-дизайна:

1. **Hero-секция** — полноэкранное видео или качественное фото блюда с тонкой типографикой. Никаких банальных «купите кейтеринг». Эмоциональный заход.
2. **Типографика** — 2 шрифта: display serif (например, Playfair Display, Cormorant, Fraunces) + clean sans-serif (Inter, Manrope, Söhne-аналог). Контраст 64px+ против 16px. Никакого Roboto/Open Sans.
3. **Цветовая палитра** — премиальная, не более 4 цветов. Рекомендация: тёмный forest green / burgundy / charcoal + тёплый кремовый + accent золото/медь. Никаких ярко-красных/синих.
4. **Воздух** — много негативного пространства. Padding между секциями минимум 120px на десктопе. Контент не «дышащий» — провал.
5. **Микро-взаимодействия** — hover-эффекты на всех интерактивных элементах. Magnetic buttons. Smooth scroll. Custom cursor для премиум-ощущения.
6. **Анимации** — scroll-triggered reveal с тонким easing (cubic-bezier). Параллакс на hero и галерее. Никаких bounce/elastic.
7. **Фотография блюд** — крупный план, естественный свет, глубина резкости. Сетка-мозаика с разным размером плиток (не uniform grid).
8. **Контент-стратегия** — короткие, емкие тексты. Заголовки 3-7 слов. Подзаголовки до 25 слов. Никаких полотен.
9. **Социальное доказательство** — реальные цифры (количество мероприятий, лет на рынке, средняя оценка). Логотипы клиентов (если есть). Отзывы с именем + фото + событием.
10. **CTA** — минимум 3 точки конверсии на каждой длинной странице. Каждая форма — не более 3 полей.

## ФАЗА 5 — ИНТЕГРАЦИЯ TELEGRAM ДЛЯ ЗАЯВОК

Все формы на сайте отправляют данные в Telegram-чат заказчика. Реализация — через Telegram Bot API напрямую из фронтенда (для статической генерации):

### 5.1. Настройка бота (заказчик делает один раз)
1. Заказчик открывает @BotFather в Telegram → `/newbot` → получает токен
2. Заказчик открывает @userinfobot → получает свой chat_id
3. Заказчик отправляет боту любое сообщение (нужно для инициализации чата)
4. Подставить значения в код:
   - `BOT_TOKEN = "[TELEGRAM_BOT_TOKEN]"`
   - `CHAT_ID = "[TELEGRAM_CHAT_ID]"`

### 5.2. Код интеграции (фронтенд)

```typescript
// src/lib/telegram.ts
const BOT_TOKEN = import.meta.env.VITE_TG_BOT_TOKEN;
const CHAT_ID = import.meta.env.VITE_TG_CHAT_ID;

export async function sendToTelegram(payload: {
  name: string;
  phone: string;
  event_type?: string;
  guests?: number;
  date?: string;
  comment?: string;
  source: string; // страница с которой пришла заявка
}) {
  const text = `
🍽 *Новая заявка с сайта Nilov Catering*

*Имя:* ${payload.name}
*Телефон:* ${payload.phone}
${payload.event_type ? `*Тип:* ${payload.event_type}` : ''}
${payload.guests ? `*Гостей:* ${payload.guests}` : ''}
${payload.date ? `*Дата:* ${payload.date}` : ''}
${payload.comment ? `*Комментарий:* ${payload.comment}` : ''}
*Источник:* ${payload.source}
*Время:* ${new Date().toLocaleString('ru-RU', { timeZone: 'Europe/Moscow' })}
`.trim();

  const url = `https://api.telegram.org/bot${BOT_TOKEN}/sendMessage`;
  const res = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      chat_id: CHAT_ID,
      text,
      parse_mode: 'Markdown',
    }),
  });
  return res.ok;
}
```

### 5.3. Безопасность
- Для production-деплоя рекомендуется проксировать через Cloudflare Function (чтобы не светить токен). Но для MVP — прямой вызов приемлем, т.к.:
  - BOT_TOKEN ограничен только отправкой сообщений в конкретный CHAT_ID
  - Любой спам блокируется настройками бота (rate limit через Telegram)
  - При компрометации — перевыпуск токена в @BotFather за 10 секунд

### 5.4. UX форм
- Все формы показывают success-состояние после отправки
- На ошибку — friendly-сообщение с предложением позвонить напрямую
- Кнопка submit показывает loading-состояние
- Поля с валидацией (телефон по маске +7, имя минимум 2 символа)

## ФАЗА 12 — ИНСТРУКЦИЯ ПО ЭКСПОРТУ И ДЕПЛОЮ

После завершения дизайна и контента — экспортируй проект для переноса на хостинг заказчика.

### 12.1. Экспорт из Lovable
1. В Lovable: Settings → GitHub → Connect to GitHub
2. Создать новый приватный репозиторий: `nilov-catering-website`
3. Lovable автоматически запушит весь код

### 12.2. Локальная сборка
```bash
git clone https://github.com/[USERNAME]/nilov-catering-website.git
cd nilov-catering-website
npm install
npm run build   # создаёт папку /dist со статическими файлами
```

### 12.3. Деплой на Timeweb (предварительно — уточнить у заказчика)
1. Заказчик логинится в панель Timeweb
2. Создаёт сайт: «Сайты» → «Добавить сайт» → «Статичный сайт»
3. Привязывает домен .ru (если ещё не привязан)
4. В разделе «Файлы» открывает менеджер файлов сайта
5. Загружает содержимое папки `/dist` (всё содержимое, не саму папку) в public_html
6. Включает SSL-сертификат (Let's Encrypt — бесплатно, кнопка «SSL»)
7. Включает HTTPS-редирект

### 12.4. Альтернатива — деплой на Vercel/Netlify (бесплатно, автоматически)
- Подключить GitHub-репозиторий к Vercel → авто-деплой при каждом пуше
- Домен .ru подключается в Vercel: Settings → Domains → Add
- Прописать DNS-записи у регистратора домена (A-запись или CNAME)

## 🆘 ЕСЛИ ЧТО-ТО НЕ ПОЛУЧАЕТСЯ

**Сайт выглядит дёшево после первой генерации:** Это нормально. Lovable генерирует базовую версию за 2 минуты, а премиальность достигается итерациями из ФАЗЫ 11. Применяй их по очереди.

**Telegram-форма не отправляет:** Проверь, что chat_id — это ID чата, а не username. И что бот был добавлен в чат (отправь ему любое сообщение первым).

**Lovable не понимает русские промпты:** Перепиши промпт на английский через DeepL — английский работает на 20-30% лучше. Но русские промпты тоже работают, просто требуют больше итераций.

**На хостинге не работает роутинг:** Для статического деплоя нужно настроить fallback на index.html. На Timeweb: добавь в .htaccess `ErrorDocument 404 /index.html`. На Vercel — автоматически.

**Сайт медленный:** Проверь, что изображения в WebP/AVIF, не превышают 200KB, и включён lazy loading. Lighthouse → Performance → посмотри Top Issues.
