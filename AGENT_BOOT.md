## BOOT SEQUENCE (выполнять ПОРЯДОЧНО)

```
1. git pull origin main
2. Проверить версию → cat VERSION.md | head -5
3. Проверить целостность → ls MEMORY/INDEX.md
4. Прочитать INDEX.md → понять какие файлы памяти существуют
5. Прочитать STATE.md → текущее состояние проекта
6. Найти релевантную память → DECISIONS.md, LEARNINGS.md по теме задачи
7. Валидировать свежесть → если исследование > 30 дней, перепроверить
8. Восстановить контекст → теперь можно работать
```

## СТРУКТУРА ПАМЯТИ

```
MEMORY/
├── INDEX.md        → Индекс всех файлов памяти (ЧТО + ГДЕ + КОГДА)
├── STATE.md        → Текущее состояние проекта (версия, статус, TODO)
├── DECISIONS.md    → Лог решений (решение/почему/альтернативы/пересмотр)
├── LEARNINGS.md    → Правила, паттерны, техники, анти-паттерны
├── RESEARCH/       → Сжатые исследования (вывод/дата/ссылка)
├── BENCHMARKS/     → Метрики качества, скоры, тренды
├── PROMPTS/        → Шаблоны промптов для восстановления контекста
├── QUALITY/        → Quality pipeline, проверки, стандарты
└── ARCHIVE/        → Устаревшие памяти (не удалять, архивировать)
```

## ПРАВИЛА ПАМЯТИ (Memory Engine)

### Что СОХРАНЯТЬ
- Решения с обоснованием (почему выбрали X, а не Y)
- Ошибки и их причины (чтобы не повторять)
- Паттерны, которые работают (подтверждённые)
- Исследования со сжатыми выводами
- Контактные данные, конфигурации, ключи

### Что НЕ сохранять
- Промежуточные рассуждения без вывода
- Дубликаты уже существующих знаний
- Сырые логи (только выжимки)
- Оценки без объективного подтверждения

### КОГДА АРХИВИРОВАТЬ
- Решение отменено или устарело
- Исследование > 90 дней без обновления
- Паттерн заменён новым
- Версия кода больше не существует

### КОГДА ОБЪЕДИНЯТЬ
- Два файла памяти затрагивают одну тему
- INDEX.md показывает > 5 записей на одну тему

### КОГДА УДАЛЯТЬ
- Никогда (только архивировать)
- Исключение: файл содержит секреты/токены

## PROTOCOL: ПОСЛЕ КАЖДОЙ ЗАДАЧИ

```
1. Что нового узнал?      → LEARNINGS.md
2. Что стало правилом?    → LEARNINGS.md (RULE)
3. Что стало шаблоном?    → PROMPTS/ или LEARNINGS.md (PATTERN)
4. Что можно автоматизировать? → LEARNINGS.md (AUTOMATE)
5. Что больше НЕ делать?  → LEARNINGS.md (NEVER)
6. Что удалить/архивировать?  → ARCHIVE/
7. Обновить STATE.md      → текущий статус
8. Обновить INDEX.md      → если созданы новые файлы
```

## PROTOCOL: ПОСЛЕ КАЖДОЙ СЕССИИ

```
1. git add -A
2. git commit -m "v[N]: [описание]"
3. git push origin main
4. Обновить VERSION.md
5. Обновить STATE.md
```

## НЕИЗМЕННЫЕ ПРАВИЛА ПРОЕКТА

1. **Каждый файл < 250 строк** — AI агенты ломают файлы > 400 строк
2. **Никаких canvas particles, 3D tilt, spring physics, morphing text**
3. **Только CSS transitions + FadeIn (IntersectionObserver)** — SSR-safe
4. **SSR-safe** — нет Math.random(), Date.now(), window в render
5. **ringColor НЕ валидный CSS** — использовать Tailwind ring-[#color]
6. **git commit + push** после каждого значимого изменения
7. **Никогда не говорить "исправлено" без объективного подтверждения**
