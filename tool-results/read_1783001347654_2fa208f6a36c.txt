     9→## 1. View Transitions API in Next.js App Router
    10→
    11→### Current State in This Project
    12→
    13→- **`next.config.ts`** has `experimental.viewTransition: true` ✅
    14→- **`ViewTransitionLink.tsx`** manually calls `document.startViewTransition()` ✅
    15→- **CRITICAL BUG:** The two approaches **CONFLICT** — when Next.js's built-in viewTransition flag is enabled, it wraps `router.push()` in its own `startViewTransition()`. The ViewTransitionLink component then wraps it in a SECOND `startViewTransition()`, creating **nested transitions that break animations**.
    16→
    17→### How Next.js 16's Built-in View Transitions Work
    18→
    19→When `experimental.viewTransition: true` is set, Next.js automatically wraps all App Router client-side navigations in `document.startViewTransition()`. This means:
    20→
    21→1. You do NOT need a custom ViewTransitionLink — regular `<Link>` gets transitions automatically
    22→2. The old/outgoing snapshot is `::view-transition-old(root)`, the new/incoming is `::view-transition-new(root)`
    23→3. You style the transition purely with CSS
    24→
    25→### ✅ Recommended Implementation (Fix the Current Setup)
    26→
    27→#### Step 1: Remove the manual ViewTransitionLink OR disable the experimental flag
    28→
    29→**Option A (RECOMMENDED): Use Next.js built-in + CSS-only animations**
    30→
    31→```css
    32→/* globals.css — Pure CSS View Transitions with Next.js 16 */
    33→

    35→::view-transition-old(root),
    36→::view-transition-new(root) {
    37→  animation: none;
    38→  mix-blend-mode: normal;
    39→}
    40→
    41→/* Custom page transition: slide + fade */

    43→  animation: 0.4s ease-in both vt-slide-out;
    44→}

    46→  animation: 0.4s ease-out both vt-slide-in;

    80→#### Step 2: Minimal JS for click-position tracking
    81→
    82→Since Next.js 16 handles the `startViewTransition()` call internally, we only need to set the CSS custom properties for origin-based transitions. Replace the entire `ViewTransitionLink.tsx` with:
    83→
    84→```tsx
    85→// src/components/ViewTransitionOrigin.tsx — Minimal click-position tracker
    86→"use client";
    87→
    88→import { useCallback, useEffect } from "react";
    89→
    90→/**
    91→ * Tracks click positions and sets --vt-x, --vt-y CSS custom properties
    92→ * on the <html> element so CSS View Transition keyframes can use them.
    93→ * Works WITH Next.js 16's built-in experimental.viewTransition.
    94→ */
    95→export default function ViewTransitionOrigin() {
    96→  const handleMouseMove = useCallback((e: MouseEvent) => {
    97→    document.documentElement.style.setProperty("--vt-x", `${e.clientX}px`);
    98→    document.documentElement.style.setProperty("--vt-y", `${e.clientY}px`);
    99→  }, []);
   100→
   101→  useEffect(() => {
   102→    document.addEventListener("mousemove", handleMouseMove, { passive: true });
   103→    return () => document.removeEventListener("mousemove", handleMouseMove);
   104→  }, [handleMouseMove]);
   105→
   106→  return null; // Renderless component
   107→}
   108→```
   109→
   110→Add to `layout.tsx`:
   111→```tsx
   112→<ViewTransitionOrigin />
   113→```

   370→### Performance Impact: CSS vs JS Animations
   371→
   372→| Metric | CSS Scroll-Driven | JS (IntersectionObserver + framer-motion) |
   373→|--------|------------------|---------------------------------------|
   374→| Thread | Compositor (main thread free) | Main thread (blocks JS) |

   377→| Battery drain | Minimal | Higher |
   378→

   421→### Haptic Feedback — Advanced Patterns
   422→
   423→```tsx
   424→// src/hooks/use-haptic.ts — Production haptic hook
   425→"use client";
   426→
   427→type HapticStyle = "light" | "medium" | "heavy" | "selection" | "success" | "warning" | "error";
   428→
   429→export function useHaptic() {
   430→  const vibrate = (style: HapticStyle) => {
   431→    // navigator.vibrate is Android-only
   432→    if (typeof navigator !== "undefined" && "vibrate" in navigator) {
   433→      const patterns: Record<HapticStyle, number | number[]> = {
   434→        light: [10],
   435→        medium: [20],
   436→        heavy: [30, 10, 30],
   437→        selection: [5],
   438→        success: [10, 50, 20],
   439→        warning: [20, 50, 20, 50, 20],
   440→        error: [30, 50, 30, 50, 30, 50, 30],
   441→      };
   442→      navigator.vibrate(patterns[style]);
   443→    }
   444→
   445→    // iOS: Use the Vibration API if available (iOS 17+)
   446→    if (typeof navigator !== "undefined" && "vibrate" in navigator === false) {
   447→      // Fallback: visual feedback for iOS
   448→      // iOS Safari does NOT support navigator.vibrate
   449→      // The only option is visual: flash/scale the element
   450→    }
   451→  };
   452→
   453→  return { vibrate };
   454→}
   455→
   456→// Usage in components:
   457→// const { vibrate } = useHaptic();
   458→// <button onClick={() => vibrate("light")}>Tap me</button>
   459→```

   479→### Swipe Gesture Best Practices for Next.js
   480→
   481→```tsx
   482→// Swipe to navigate between pages (like iOS back gesture)
   483→"use client";
   484→
   485→import { useRouter } from "next/navigation";
   486→import { useEffect, useRef } from "react";
   487→
   488→export function useSwipeBack(threshold = 100) {
   489→  const router = useRouter();
   490→  const startX = useRef(0);
   491→  const startY = useRef(0);
   492→
   493→  useEffect(() => {
   494→    // Only on touch devices
   495→    if (!("ontouchstart" in window)) return;
   496→
   497→    const handleStart = (e: TouchEvent) => {
   498→      // Only trigger from left edge (like iOS)
   499→      if (e.touches[0].clientX < 30) {
   500→        startX.current = e.touches[0].clientX;
   501→        startY.current = e.touches[0].clientY;
   502→      }
   503→    };
   504→
   505→    const handleEnd = (e: TouchEvent) => {
   506→      const dx = e.changedTouches[0].clientX - startX.current;
   507→      const dy = e.changedTouches[0].clientY - startY.current;
   508→      // Must be mostly horizontal, from left edge, with sufficient distance
   509→      if (dx > threshold && Math.abs(dx) > Math.abs(dy) * 2) {
   510→        router.back();
   511→      }
   512→    };
   513→
   514→    document.addEventListener("touchstart", handleStart, { passive: true });
   515→    document.addEventListener("touchend", handleEnd, { passive: true });
   516→
   517→    return () => {
   518→      document.removeEventListener("touchstart", handleStart);
   519→      document.removeEventListener("touchend", handleEnd);
   520→    };
   521→  }, [router, threshold]);
   522→}
   523→```

   688→### 🔥 Hack 1: CSS `@starting-style` for Entry Animations (Chrome 117+)

   690→Animate from `display: none` to visible WITHOUT JavaScript:

   697→  display: block;
   698→  @starting-style {

   701→  }
   702→  transition: opacity 0.5s, transform 0.5s;
   703→  opacity: 1;
   704→  transform: translateY(0);
   705→}
   706→```
   707→
   708→### 🔥 Hack 2: `view-transition-class` for Per-Page Transition Styles (Chrome 125+)
   709→
   710→Assign different transition animations based on the page being navigated to:
   711→
   712→```css
   713→/* When navigating TO the gallery page */
   714→:root:has(.gallery-page) {
   715→  view-transition-class: gallery-transition;
   716→}
   717→
   718→.gallery-transition::view-transition-old(root) {
   719→  animation: 0.6s ease-out both vt-zoom-out;
   720→}
   721→.gallery-transition::view-transition-new(root) {
   722→  animation: 0.6s ease-out both vt-zoom-in;
   723→}
   724→```
   725→
   726→### 🔥 Hack 3: Lenis + Scroll-Driven Animations Integration
   727→
   728→The issue: Lenis virtualizes scroll position, which breaks `animation-timeline: scroll()`. The fix:
   729→
   730→```css
   731→/* Lenis uses transform on the wrapper, which breaks scroll() timeline */
   732→/* Solution: Use view() timeline instead, which works with Lenis! */
   733→/* Or: configure Lenis to use native scroll */
   734→```
   735→
   736→```tsx
   737→// In SmoothScroll.tsx, add:
   738→const lenis = new Lenis({
   739→  // ... existing config ...
   740→  // CRITICAL: This makes Lenis use native scrolling instead of transforms
   741→  // which allows animation-timeline: scroll() to work
   742→  __experimentalScrollMode: 'native', // Lenis 1.3+ 
   743→});
   744→```
   745→
   746→Actually, the real fix is simpler — use `animation-timeline: view()` (which works regardless of scroll method) instead of `scroll()` where possible. The `view()` timeline is based on element visibility, not scroll position.
   747→
   748→### 🔥 Hack 4: `transition-behavior: allow-discrete` (Chrome 117+)
   749→
   750→Allows transitioning `display: none` ↔ `display: block`:

   752→```css
   753→.modal {
   754→  transition: opacity 0.3s, display 0.3s allow-discrete;
   755→}
   756→.modal.closed {
   757→  opacity: 0;
   758→  display: none;
   759→}
   760→```
