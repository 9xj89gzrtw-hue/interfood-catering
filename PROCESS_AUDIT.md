## 2. КОРНЕВЫЕ ПРИЧИНЫ — ПОЧЕМУ ПРОЦЕСС ЛОМАЕТСЯ

### 2.1. ИЛЛЮЗИЯ ВЕРИФИКАЦИИ
**Проблема:** Все проверки — статический анализ кода. Ни одна не проверяет РЕАЛЬНЫЙ рендер.

**Механизм:**
- `npm run build` → ✅ — означает лишь что JSX компилируется
- HTTP 200 → ✅ — означает лишь что сервер отвечает
- `grep "menu-builder" page.tsx` → ✅ — строка в коде, не работающий компонент
- TypeScript `--noEmit` → ✅ — но `ignoreBuildErrors: true` в next.config.ts обходит это

**Следствие:** Каждый "✅ PASS" увеличивает уверенность без увеличения реального качества.

### 2.2. НЕТ РАЗЛИЧЕНИЯ МЕЖДУ "КОД НАПИСАН" И "КОД РАБОТАЕТ"
**Проблема:** После написания кода сразу commit + push + deploy.

**Механизм:**
- Написал код → build проходит → push → deploy → "✅ готово"
- Никогда не открывается реальный браузер
- Никогда не проверяется: а КЛИКАЕТСЯ ли кнопка? а ВИДЕН ли текст? а СКРОЛЛИТСЯ ли секция?

### 2.3. КОЛИЧЕСТВО ВМЕСТО КАЧЕСТВА
**Проблема:** v81 добавила "60+ WOW-эффектов". Каждый новый эффект — потенциальный источник регрессии.

**Механизм:**
- 60+ новых эффектов = 60+ новых точек отказа
- Чем больше эффектов, тем выше вероятность z-index конфликта
- Чем больше эффектов, тем хуже производительность
- Ни один эффект не был протестирован на реальном устройстве

### 2.4. ПАРАЛЛЕЛЬНЫЕ АГЕНТЫ БЕЗ КООРДИНАЦИИ
**Проблема:** 4-6 параллельных агентов пишут код одновременно.

**Механизм:**
- Агент A пишет анимацию с z-index: 30
- Агент B пишет навигацию с z-index: 9999
- Агент C добавляет overlay с pointer-events: none
- Результат: кнопки не нажимаются, элементы перекрываются
- Ни один агент не знает что делают другие

### 2.5. "ИСПРАВЛЕНО" БЕЗ ПОДТВЕРЖДЕНИЯ
**Проблема:** Каждое исправление маркируется ✅ без объективной проверки.

**Механизм:**
- "✅ Добавлена ссылка в навигацию" — но не проверено, работает ли smooth scroll
- "✅ Grain overlay z-index: 50" — но не проверено, не перекрывает ли что-то ещё
- "✅ Sticky header: top-16" — но не проверено, не перекрывает ли PDF кнопку

### 2.6. REGRESSION AMNESIA
**Проблема:** Нет реестра известных багов. Нет проверки что старые баги не вернулись.

**Механизм:**
- v72: Исправлено 262 сломанных медиа-ссылки
- v80: Полная переработка — кто проверил что медиа-ссылки не сломались снова?
- v73: Исправлен body color
- v80: Переписаны все компоненты — кто проверил что body color правильный?

## 3. ФОРМАЛЬНЫЕ ПРОВЕРКИ — ЧТО ДЕЛАЕТСЯ "ДЛЯ ГАЛОЧКИ"

| Действие | Формальность | Почему |
|----------|-------------|--------|
| `npm run build` | ФОРМАЛЬНОСТЬ | С `ignoreBuildErrors: true` это не проверка |
| TypeScript `--noEmit` | ЧАСТИЧНО | Проверяет типы, но ошибки игнорируются при сборке |
| HTTP 200 проверка маршрутов | ФОРМАЛЬНОСТЬ | Страница может быть пустой/сломанной и вернуть 200 |
| "Все критические файлы существуют" | ФОРМАЛЬНОСТЬ | Файл может существовать и быть пустым |
| "MenuBuilder на главной" | ФОРМАЛЬНОСТЬ | `grep "menu-builder"` ≠ работающий компонент |
| "Нет pointer-events:none" | ФОРМАЛЬНОСТЬ | Grep по исходнику не учитывает runtime рендер |
| "Footer тёмный фон" | ФОРМАЛЬНОСТЬ | Проверяет строку в файле, не визуальный результат |
| Обновление VERSION.md | ФОРМАЛЬНОСТЬ | Запись в файл ≠ реальное улучшение |

## 5. НОВЫЙ ПРОЦЕСС — РАБОЧИЙ ЦИКЛ С QUALITY GATES

### ПРИНЦИПЫ:

1. **"Сборка прошла" ≠ "Сайт работает"** — никогда не приравнивать
2. **После каждого изменения — искать что сломалось**, а не доказывать что всё хорошо
3. **Реальный браузер — обязательный этап**, а не опциональный
4. **Каждый ✅ должен иметь объективное подтверждение** — скриншот, лог, или результат команды
5. **Параллельные агенты — только для НЕЗАВИСИМЫХ задач** с обязательной интеграционной проверкой
6. **Не более 3 изменений за итерацию** — меньше изменений = меньше регрессий

### ФАЗЫ РАБОЧЕГО ЦИКЛА:

```
ФАЗА 1: АНАЛИЗ (не трогать код!)
├── Что конкретно нужно изменить?
├── Какие файлы затронуты?
├── Какие компоненты МОГУТ сломаться?
├── Какие z-index/pointer-events/conflicts возможны?
└── Записать в WORKLOG: план с конкретными файлами

ФАЗА 2: ИЗМЕНЕНИЕ (минимальное)
├── Изменить ТОЛЬКО запланированное
├── Не добавлять "пока здесь" улучшения
├── Не трогать файлы, не связанные с задачей
└── Каждый файл — отдельный осознанный выбор

ФАЗА 3: СТАТИЧЕСКАЯ ПРОВЕРКА
├── npm run build (БЕЗ ignoreBuildErrors!)
├── npx tsc --noEmit
├── grep на сломанные ссылки
└── Если ЛЮБАЯ ошибка → ФАЗА 2 (исправить, не обходить)

ФАЗА 4: РЕАЛЬНАЯ ПРОВЕРКА (agent-browser)
├── Открыть каждую затронутую страницу
├── Проверить console errors
├── Кликнуть на КАЖДЫЙ интерактивный элемент
├── Проверить mobile viewport
├── Проверить что старый функционал работает
└── СКРИНШОТ как доказательство

ФАЗА 5: ПОИСК ОШИБОК (внутренний критик)
├── "Что МОГЛО сломаться?"
├── "Какие z-index конфликты возможны?"
├── "Работает ли это на мобильном?"
├── "Не перекрыт ли какой-нибудь элемент?"
└── Проверить ВСЕ гипотезы через agent-browser

ФАЗА 6: РЕШЕНИЕ
├── Если найдены ошибки → ФАЗА 2 (исправить) → повторить ФАЗЫ 3-5
├── Если 2 полных цикла без новых ошибок → можно commit
└── НИКОГДА не commit после первого прохода
```

## 6. НОВЫЕ QUALITY GATES — ЗАМЕНЯЮТ СТАРЫЕ

### Gate A: СТАТИЧЕСКИЕ (быстрые, обязательные)

| Gate | Проверка | Объективный критерий |
|------|---------|---------------------|
| A1 | Build без ignoreBuildErrors | `npm run build` + нет ошибок |
| A2 | TypeScript чистый | `npx tsc --noEmit` = 0 ошибок |
| A3 | Нет сломанных медиа | Все /images/* refs существуют |
| A4 | Нет дублирующихся CSS свойств | Автоматический grep |
| A5 | Критические файлы существуют | Проверка ls |

### Gate B: РЕНДЕРИНГ (agent-browser, обязательные)

| Gate | Проверка | Объективный критерий |
|------|---------|---------------------|
| B1 | Console errors = 0 | `agent-browser errors` → пусто |
| B2 | Все CTA кликабельны | Каждый CTA button/link кликается без "covered by" |
| B3 | Навигация работает | Каждая ссылка → правильный URL/якорь |
| B4 | MenuBuilder работает | Добавить блюдо → PDF кнопка enabled → PDF скачивается |
| B5 | Mobile viewport OK | viewport 375x812 → все элементы доступны |
| B6 | Футер виден | Footer не скрыт, контакты видны |

### Gate C: РЕГРЕССИЯ (после каждого изменения)

| Gate | Проверка | Объективный критерий |
|------|---------|---------------------|
| C1 | Старые баги не вернулись | Проверка из реестра багов |
| C2 | Предыдущий функционал работает | Тест критических пользовательских путей |
| C3 | Производительность не деградировала | Время загрузки hero < 5s |

## 8. ПРАВИЛА ДЛЯ ВСЕХ ПОСЛЕДУЮЩИХ ЗАДАЧ

1. **НЕ commit/push/deploy** без прохождения Gate A + B + C
2. **НЕ добавлять** новые эффекты пока существующие баги не исправлены
3. **НЕ использовать** `ignoreBuildErrors: true` — это маскировка проблем
4. **НЕ писать** "✅ исправлено" без скриншота/лога/результата команды
5. **НЕ запускать** более 2 параллельных агентов для кода (координация стоит дороже)
6. **НЕ менять** более 5 файлов за одну итерацию
7. **ВСЕГДА** проверять реальный сайт в браузере после deploy
8. **ВСЕГДА** проверять мобильную версию отдельно
9. **ВСЕГДА** обновлять реестр багов
10. **ВСЕГДА** записывать объективное подтверждение в WORKLOG
