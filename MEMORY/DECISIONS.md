## D-001: Editorial Minimalism вместо Ultra WOW

- **Решение:** Полный отказ от 40+ анимационных компонентов. Замена на простые CSS transitions + FadeIn.
- **Почему:** 40+ компонентов (CinematicHero 1332 строки, ParticleField, MorphingText, TiltCard и т.д.) привели к: SSR ошибкам, пустым белым зонам, сломанной мобильной версии, hydration mismatch. Пользователь подтвердил: "сайт не рабочий".
- **Альтернативы:** (1) Починить существующие анимации — отвергнуто:太多 inter-dependencies; (2) Оставить некоторые — отвергнуто: каждая сложная анимация потенциальный источник SSR бага
- **Пересмотреть:** Если потребуется "wow-эффект" для инвесторов — только через CSS-only scroll-driven animations (Chrome 115+), с graceful degradation
- **Дата:** 2026-07-02

## D-002: Один файл < 250 строк

- **Решение:** Жёсткий лимит — каждый файл не более 250 строк.
- **Почему:** Эксперимент Zero Human Code (2026) доказал: AI-агенты начинают ошибаться в файлах > 400 строк. В проекте были файлы 800-1332 строки, и все содержали баги.
- **Альтернативы:** (1) Лимит 400 строк — отвергнуто: слишком близко к порогу ошибок; (2) Без лимита — отвергнуто: уже привело к катастрофе
- **Пересмотреть:** Если появится инструмент автоматической проверки длины файлов в CI/CD
- **Дата:** 2026-07-02

## D-003: Warm Biophilic Luxury вместо Light Premium

- **Решение:** Смена палитры с #FAFAF7 (нейтральный белый) + #B8860B (тёмное золото) на #F5F1EA (тёплый крем) + #D4A843 (золотой шафран).
- **Почему:** (1) Цвета 2026 для food/hospitality — тёплые тона бьют холодные (Coloracci); (2) #FAFAF7 слишком стерилен для еды; (3) #B8860B слишком агрессивен для "редакционного" стиля
- **Альтернативы:** (1) Оставить Light Premium — отвергнуто: слишком "корпоративный" вид; (2) Dark premium — отвергнуто: не конвертирует для кейтеринга
- **Пересмотреть:** При ребрендинге или если A/B тест покажет лучшую конверсию другой палитры
- **Дата:** 2026-07-03

## D-004: SubpageLayout — единый шаблон для подстраниц

- **Решение:** Создать SubpageLayout.tsx (~200 строк) с навигацией, футером, WhatsApp и общим стилем. Все подстраницы используют его.
- **Почему:** 16 подстраниц с дублированным кодом навигации/футера = 16 мест для багов. Единый шаблон = одно место для фикса.
- **Альтернативы:** (1) Layout в app/ — можно, но ограничивает кастомизацию hero-секций; (2) React context — overengineering
- **Пересмотреть:** Если подстраницам потребуется существенно разная структура
- **Дата:** 2026-07-03

## D-005: WhatsApp как основной CTA вместо форм

- **Решение:** Все CTA кнопки ведут на WhatsApp (wa.me/79119417205) с предзаполненным текстом, а не на формы.
- **Почему:** (1) Формы в кейтеринге конвертируют хуже мессенджеров (пользователь хочет быстрый ответ); (2) Формы ломались (кнопка disabled, email не доходил); (3) WhatsApp даёт мгновенный контакт
- **Альтернативы:** (1) Формы + WhatsApp параллельно — можно для /contacts, но не для основных CTA; (2) Telegram как основной — отвергнуто: WhatsApp популярнее в РФ
- **Пересмотреть:** Если подключим CRM с автоматической обработкой форм
- **Дата:** 2026-07-03

## D-006: Agent OS вместо монолитного MEMORY.md

- **Решение:** Заменить один MEMORY.md (бесконтрольно растущий) на структурированную MEMORY/ директорию с индексом, специализированными файлами и правилами сжатия.
- **Почему:** (1) MEMORY.md вырос до 600+ строк с противоречиями (v84 vs v90 информация); (2) Нет механизма архивации устаревшего; (3) Исследования zylos.ai показывают: успешные агентные системы используют индексированную память с сжатием, а не один файл; (4) arXiv:2606.15828 предупреждает о "context bloat" в AGENTS.md
- **Альтернативы:** (1) Продолжать расширять MEMORY.md — отвергнуто: уже привело к противоречиям; (2) Внешняя БД — overengineering для текущего масштаба
- **Пересмотреть:** Когда проект вырастет до 50+ страниц или 3+ разработчиков
- **Дата:** 2026-07-03

## D-007: "use client" вместо ssr: false

- **Решение:** Для клиентских компонентов использовать директиву `"use client"` вместо `dynamic(() => import(...), { ssr: false })`.
- **Почему:** В Next.js 16 `ssr: false` не работает в Server Components — вызывает ошибку. `"use client"` — официальный способ.
- **Альтернативы:** Нет реальных альтернатив в Next.js 16
- **Пересмотреть:** Только при обновлении Next.js
- **Дата:** 2026-07-02
